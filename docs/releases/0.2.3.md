# Tuya BLE Access 0.2.3

In 0.2.2, `TyOS` discovery immediately checked credentials. A missing key or
cloud failure could abort the flow before the discovery card was shown.

Discovery now first shows **Bluetooth lock found: check credentials** without
logging in to Tuya or changing Bluetooth pairing. Continue explicitly to check
stored keys and, if needed, the configured account. Failed checks remain visible
and retryable. A successful check opens a separate reactivation confirmation.

The integration guide now maps each device state to its next step and explains
that adding a paired lock, updating HA, missing discovery and Bluetooth timeouts
do not require factory reset.

Tests cover discovery/polling without cloud or pairing calls, retry after a
failed check, and separate confirmation before pairing. Existing activation and
local credential reuse tests follow the new check step. Physical verification
of the revised flow on the production lock remains outstanding.

Update the integration and restart Home Assistant. Wake the lock near the
Bluetooth proxy to trigger fresh discovery. No factory reset is required.
