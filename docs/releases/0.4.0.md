# 0.4.0 — Access manager and remembered PINs

Adds an administrator-only **Tuya BLE Access** sidebar page. Each lock has one
list of saved PINs, temporary PINs, cards and fingerprints, showing label,
person, type, status and validity. Technical slot/policy fields and PIN digits
are excluded from the manager response and display. Retained expired or archived
temporary entries remain visible with their lifecycle status.

Add access, edit a label or person, and pause or resume directly from each row.
Label/person edits are local metadata changes: they preserve the enrollment,
original device member, validity and remembered PIN. Person association can be
removed without affecting another credential of the same member. The page has
English/Dutch text and a compact layout for phones.

Ordinary PIN pause/resume is now enabled for the verified ba2qk177 Keybox. The
firmware requires the PIN digits alongside the schedule. Physical testing
confirmed the same PIN opened initially, was rejected after pausing, and opened
after restoring the original schedule. The earlier zero-length PIN command was
rejected and did not block access.

New ordinary PIN enrollments always remember the code locally. Existing PINs
with known enrollment policy need their original code supplied once; subsequent
pause/resume calls use the remembered code, including after an HA restart. A
different supplied code cannot silently replace a remembered one. The private
HA storage file uses restricted file permissions and atomic writes; the PIN is
not separately encrypted and may be present in HA backups. The manager does
not return PIN values. Deleting/replacing the local record forgets its PIN.

The full DP54 inventory query now uses the combined method marker. A single-type
query had missed an enrolled ordinary PIN during physical verification. No reply
is treated as an unconfirmed inventory, not proof that a lock is empty.

Deletion of ordinary credentials requires known enrollment policy and a matching
DP2 success response before removing the local record. Wrong-lock IDs, unknown
policies and rejected replies retain the registration. The manager asks for
confirmation before deletion. Expired temporary PIN cleanup remains automatic.

Existing records are preserved on update. Missing enrollment policies from older
versions cannot be reconstructed from labels, persons or a PIN alone. Admin and
limited-use credentials, whole-person suspension and other product profiles are
not newly enabled. Keybox reboot/day rollover behavior remains untested. The
new panel's interactions were checked with simulated HA responses. Registration
in the HA sidebar, its administrator-only configuration, the empty-list service
response and private PIN persistence were also checked in isolated Home Assistant
2026.8.3 without Bluetooth access. Production HA has not been restarted or updated
during release preparation.

Update through HACS, restart Home Assistant, and open **Tuya BLE Access** in the
sidebar. No lock reset or new Tuya pairing is required.
