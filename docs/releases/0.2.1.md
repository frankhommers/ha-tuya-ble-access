# Tuya BLE Access 0.2.1

This release brings the Home Assistant integration's K3 BLE PRO 2 work together:
local activation entry points, unlock attribution, English/Dutch translations,
hardware-reset reporting and temporary PIN lifecycle management.

## Changes

- Rename the project to Tuya BLE Access and the domain to `tuya_ble_access`.
  Existing installations must follow the [domain migration guide](../domain-migration.md);
  explicit service calls and event triggers need updating.
- Release the project under the MIT [LICENSE](../../LICENSE).
- Identify enrolled fingerprints/cards/PINs in unlock history where the device
  supplies a matching hardware ID. Deduplicate repeated unlock records.
- Observe K3 event flags and connect on demand; persistent connection remains optional.
- Provide English and Dutch entity, action, option and error translations.
- Report a physical factory reset to clear this lock's old HA mappings while
  retaining people and other locks. This action does not reset the hardware.
- Convert temporary-PIN validity using the HA time zone or explicit UTC offset;
  reject ambiguous/nonexistent local times and invalid periods.
- Require a successful temporary-PIN creation response with a valid hardware ID.
  Attribute use via `tuya_ble_access_temporary_code_used` and its `password_id`.
- Remove expired temporary PINs on normal connections after a matching deletion
  confirmation. Preserve historical names in an archive. No additional periodic
  connections are created for cleanup.

## Upgrade notes

Select option values use language-independent keys. Automations that pass English
display labels to `select.select_option` must use the underlying keys instead
(for example `Normal` becomes `normal`). Check the entity's `options` attribute.
Previously stored select display labels are handled during state restoration.

Old temporary-PIN entries without a confirmed hardware ID remain unverified and
cannot be attributed or automatically removed by guessing an ID.

## Validation and limits

Validated in the development Home Assistant 2026.8.3 environment, including
domain migration and restart with all 22 entity IDs, both device IDs and both
credential stores preserved. All 239 offline tests pass. Offline tests
exercise protocol messages, time-zone boundaries, storage, failure handling,
event attribution and cleanup. Captured K3 traffic informed event handling.

Temporary-PIN creation, opening within the validity period, refusal outside it
and deletion acknowledgement still require a physical test on K3 firmware.
Treat those features as experimental. Existing V3/V4 device profiles have not
been physically retested for this release. Passive ESPHome scanning has not been
enabled or claimed as validated in this release.

The release artifact contains only `custom_components/tuya_ble_access/`. Research
tools, Android NFC Lab, captures and app analyses are not part of the release.
