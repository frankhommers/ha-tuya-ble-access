# Tuya BLE Access 0.2.2

Bluetooth discovery previously offered a factory-reset/activation prompt based
on the advertised name `TyOS`, before checking whether credentials existed.
Repeated 30-second Bluetooth timeouts could then leave Add spinning for minutes.

## Changes

- Explain initial Tuya Smart / Smart Life pairing in the add-lock flow in Dutch
  and English. A normally paired lock is imported without a factory reset.
- Check stored device keys and cached activation keys by MAC first. Only consult
  the configured Tuya account if usable local credentials are missing.
- Require a matched cloud lock and complete, validated credentials before showing
  cloud-backed activation confirmation. Account lookup failures are distinct
  from an account that does not contain the device.
- Persist checked activation credentials separately before Bluetooth pairing.
  Failed attempts can be retried without another cloud login, even after restart.
  Confirmation shows whether keys are local or fetched from Tuya.
- Reuse checked keys on confirmation; coordinate reactivation with the existing
  device coordinator so it cannot compete for the same Bluetooth connection.
- Bound the initial device-info phase to 45 seconds, before sending PAIR.
  Tuya HTTP calls time out after 15 seconds; activation preflight has a total
  30-second cloud deadline. Connection errors give actionable guidance.
- Do not log full Tuya authentication requests or successful API responses.

## Validation and limitations

Automated tests cover credential validation, account lookup failures, local key
reuse, persistence across store instances, concurrent seed saves, failed pairing
retries without cloud access, and Bluetooth timeout cancellation before PAIR.
The release ZIP is built and verified against the source.

This release has not yet been physically validated on the production lock.
Stored keys permit an offline attempt; acceptance still depends on the lock and
its current pairing state. A timeout does not establish that a reset is needed.
The advanced `activate` action retains its cloud-fetch behavior; local-first
reactivation is provided through discovery. Temporary PIN lifecycle validation
remains experimental as described in the 0.2.1 release notes.

After updating, restart Home Assistant and reopen discovery to start a fresh
flow. Existing device records are preserved; no factory reset is required for
this update.
